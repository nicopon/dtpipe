dtpipe distributed lab

A coordinator splits a dtpipe pipeline into fragments and runs each on the node that holds its data; Arrow streams carry the rows between nodes. This stack runs the whole lab in containers, each on its own data only.

Services

ServiceWhat it does
proxyThis page, and the only published port: routes each host name to its service.
idpTest OpenID Connect provider: client credentials for the nodes, a sign-in form for people.
coordinatorThe control plane, in lab mode: plans, deploys and runs pipelines, holds the library (a git repository) and the rights.
node-1 … node-4Data nodes, each with its own database, seeded on first start. They serve no HTTP: their state is in the coordinator's Nodes view.
runner-1The official runner: holds no data, carries every step between the bricks.

From a terminal

cd samples/distributed-lab
docker compose ps                 # which services run
docker compose logs -f coordinator
docker compose down               # .stack/ keeps the data; delete it to seed again
